Migración XuperTV a Tizen

Qué se cambió para que el port de webOS funcione en un Samsung Tizen 9 (UN50U8000FKXZL), qué se probó y qué falta para soportar bien las listas M3U.

Estado actual

FunciónEstadoNota
Instalación y firmaFuncionaPaquete XuperTVapp, firmado con certificado Samsung Partner del TV
Botón Atrás / salirFuncionaSe traduce 10009 a la tecla Back que espera app.js
Listas M3U (Addons)FuncionaProbado en el TV: lista de Colombia de iptv-org, 162 canales en 0,6 s, video 1920×1080
Videos demo de catalog.jsFuncionaTienen streamUrl directo
Catálogo y canales del portalNo soportadoFuera del alcance de este port; el puente responde “no disponible”

Cambios hechos

  1. ID de paquete. Tizen exige exactamente 10 caracteres alfanuméricos. XuperTV fallaba con install failed[118, -4] Load archive info fail. Ahora: package="XuperTVapp", id="XuperTVapp.XuperTV", nombre visible TizenXuperTV.
  2. Tecla Atrás. El control envía keyCode 10009 (XF86Back), pero app.js solo reacciona a 461, "Back" o "GoBack". En tizen-bridge.js se intercepta 10009 en captura y se re-emite como KeyboardEvent('keydown', { key: 'Back' }).
  3. Salir desde la primera pestaña. app.js llama a window.webOSTV.platformBack(), que no existe en Tizen. Se define window.webOSTV.platformBack → tizen.application.getCurrentApplication().exit(). No se define window.PalmSystem: webOSTV.js lo usa para decidir si corre en webOS.
  4. Créditos. index.html: “Port LG webOS CRISTIANCODEV” → “TizenXuperTV”. js/app.js (Acerca de): “Port para LG webOS realizado por CristiancoDEV” → “TizenXuperTV”. config.xml: <author>TizenXuperTV</author>.
  5. Puente de servicio local. En webOS, app.js habla con su servicio por PalmServiceBridge → luna://. Tizen no tiene ese bus, así que tizen-bridge.js define un PalmServiceBridge propio que responde dentro de la página. app.js no se tocó.

Qué falta para soportar bien las listas

En orden de impacto. Ninguno requiere cambiar la parte del portal.

Alta

Reproducir con AVPlay en vez de <video> + hls.js

El reproductor nativo de Samsung (webapis.avplay) decodifica por hardware, acepta HLS, DASH y MPEG-TS, y abre más rápido. Muchas listas IPTV traen .ts o HLS con códecs que hls.js maneja mal en el TV. Requiere <script src="$WEBAPIS/webapis/webapis.js"> y un <object type="application/avplayer">.

Alta

Listas grandes sin congelar la UI

Bt() crea un nodo DOM por canal de una vez. Con listas de miles de canales (por ejemplo el índice completo de iptv-org) la TV se congela. Hace falta una lista virtualizada (solo las filas visibles) y parsear el M3U por partes.

Alta

Acceso visible a “Agregar lista”

Hoy el diálogo de listas solo se abre desde el reproductor: canal en pantalla completa → ← (panel de canales) → pestaña “➕ Addons M3U” → “Administrar Addons y Listas M3U”. Hace falta un acceso directo en la pestaña TV o en Ajustes.

Media

Grupos de la lista como categorías

El parser ya devuelve group (group-title o #EXTGRP), pero la UI muestra todo en una sola lista “Addons M3U”. Usarlo para filtrar como las categorías del portal.

Media

Canales caídos y bloqueados por país

Hoy un canal que no responde se queda en “Cargando señal…”. Agregar un tiempo límite (8–10 s), mensaje claro y opción de pasar al siguiente. En iptv-org vienen marcados con [Geo-blocked] en el nombre.

Media

Guía de programación (EPG)

Leer url-tvg / x-tvg-url de la cabecera #EXTM3U, descargar el XMLTV y cruzar por tvg-id. La barra de info del reproductor ya tiene los campos “ahora / siguiente”.

Baja

Persistencia y edición de listas

Las listas agregadas se guardan en el TV; falta poder borrarlas y renombrarlas desde la UI, y refrescarlas en segundo plano.

Baja

Arranque más rápido

data/portal.js (507 KB) se carga siempre aunque en Tizen no se use para reproducir. Cargarlo después de mostrar la primera pantalla, o no incluirlo en el build de Tizen.

Compilar, firmar e instalar

Archivos en Projects/Samsung TV/XuperTV-Tizen-port/: src/js/tizen-bridge.js, tools/resign_wgt.py (firma autor + distribuidor sin Tizen Studio, solo Python y OpenSSL) y build/TizenXuperTV_1.6.19_signed.wgt.

# 1. Firmar con el certificado que genera Apps2Samsung (DUID del TV incluido)
python3 -I tools/resign_wgt.py app.wgt app_signed.wgt \
  "$HOME/Library/Application Support/Apps2Samsung/Certificate/<perfil>" /tmp/work

# 2. Instalar (Developer Mode activo y Host PC IP = IP de la Mac)
sdb connect 192.168.1.5
sdb push app_signed.wgt /home/owner/share/tmp/sdk_tools/tmp/app.wgt
sdb shell 0 vd_appinstall XuperTVapp.XuperTV /home/owner/share/tmp/sdk_tools/tmp/app.wgt

# 3. Depurar con DevTools
sdb shell 0 debug XuperTVapp.XuperTV        # devuelve el puerto
sdb forward tcp:9333 tcp:<puerto>           # abrir http://127.0.0.1:9333

Al reinstalar, la versión de config.xml debe subir y la firma debe ser del mismo certificado; si no, hay que desinstalar antes.
